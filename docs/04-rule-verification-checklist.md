# 4. Rule Verification Checklist

No threshold may be used in a real check until every step below is complete.
The tool must never claim a value is verified when it is not.

## 4.1 Who verifies

Every rule needs two independent sign-offs:

- **Practising architect** (Italian professional registration, e.g. Ordine degli Architetti):
  confirms the rule applies in real design practice and that the threshold is applied as
  practitioners apply it.
- **University professor** (teaching accessibility or building regulation): confirms the
  article reading against the official text and the teaching explanation.

Both sign the rule register. A rule is Verified only when both have signed. Neither role
replaces a formal legal opinion for a specific building.

## 4.2 Steps for each rule

1. **Identify the source.** Name the regulation (e.g., DM 236/1989 for accessibility of
   buildings) and confirm it applies to the building type in question.
2. **Read the official text.** Use the official publication or its official source,
   not a summary, forum, or AI-generated answer.
3. **Locate the article.** Record the exact article and paragraph number.
4. **Record the value.** Enter the threshold, unit, and operator exactly as written.
   Note any conditions (building type, door type, exceptions).
5. **Check exceptions.** Note any exemption or alternative provision that changes the value.
6. **Record the verifier, role, and date** in the rule register (architect and professor columns).
7. **Second check.** The second verifier (the other role from 4.1) confirms steps 2 to 6.
8. **Mark status** as Verified in the rule register.

## 4.3 Rule register status values

| Status | Meaning | Usable in real projects? |
|---|---|---|
| Placeholder | Value not yet checked | No |
| Needs review | Value entered, not yet second-checked | No |
| Verified | Two people have checked against the official text | Yes |
| Superseded | Regulation changed; kept for history | No |

## 4.4 Re-verification

- Re-verify all rules when the regulation is amended or replaced.
- Re-verify when a project is subject to a different regional or local rule.
- Record each re-verification as a new row, not an overwrite, so history is kept.

## 4.6 Important limitations

- The register holds only rules that can be checked from model data. Many accessibility
  requirements (e.g., tactile paving, lighting levels, signage) cannot be checked this way.
- A pass in this tool does not mean the building complies with all requirements.
